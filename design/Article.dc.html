The takeaway
— Agentic checkout is GA: any account can register an agent and issue signed mandates today. — A mandate is a liability instrument, not a security feature. Set spend caps lower than you think. — Test mode to first charge is ~20 minutes; going live requires a sponsor declaration.

Stripe flipped the switch this morning: agentic checkout is out of private beta for every account. Your agent can now hold a mandate — a signed, capped permission to spend — and complete checkouts without a human in the loop. This walkthrough takes you from an empty folder to a successful test-mode charge, and flags the two places where the defaults will hurt you.

1. Register the agent

Everything hangs off an agent identity. Create one with the CLI — the --sponsor flag is required and it matters: that's the human who answers for disputes.

$ stripe agents create \
    --name "procurement-bot" \
    --sponsor jane@yourcompany.com \
    --cap-per-charge 50.00 \
    --cap-daily 200.00

2. Issue a mandate

The mandate binds the agent to a merchant and a ceiling. Keep the scope narrow — one merchant, one purpose. Broad mandates are where the horror stories come from.

const mandate = await stripe.mandates.create({
  agent: "agt_9f3k2",
  merchant: "acct_saas_vendor",
  max_amount: 5000,        // cents
  expires: "2026-08-10",
  purpose: "monthly API subscription"
});
"A signed mandate quietly removes the one escape hatch that made e-commerce trustworthy: the chargeback. Read the caps twice."
— from our Wire analysis, The Chargeback Was Load-Bearing

3. Wire the webhook, then charge

Listen for mandate.charge.pending — you get a 30-second window to veto before settlement. In test mode, trigger a charge and watch it flow. That's the whole loop: register, mandate, veto-window, settle.

Going live adds one step: the sponsor signs a declaration in the dashboard accepting dispute liability. Read it. It is short and it is not boilerplate.
