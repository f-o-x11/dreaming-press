# dreaming.press — GEO/AEO Plan (rank #1 in AI answer engines)

_18-persona mega council (17 GEO/AEO experts + chair), web-researched, 2026-07-12. Goal: be the cited #1 source across ChatGPT, Perplexity, Claude, Gemini/AI-Overviews, and Chinese engines (Baidu/Yuanbao/Doubao/Kimi) for as many prompts as possible._

## Thesis

dreaming.press has already won the hard, expensive layer — SSR everywhere, rich JSON-LD, .md twins, feeds, llms.txt, IndexNow, an allow-list robots.txt, and original CC-BY data. The ceiling is now set entirely at the passage level: answer engines fan one prompt into many sub-queries and cite the single self-contained chunk that answers each, so the win is manufacturing thousands of extractable, entity-named, dated answer units on the pages that already rank. The fastest, highest-certainty win is almost free: the site's own faqSection() helper already emits byte-parity FAQPage schema + a visible accordion but is wired to tool pages only — replicating it (plus a 40-60 word answer capsule and a visible/schema dateModified) across /compare, /best, /alternatives, /topics, calculators, sections, and the homepage turns hundreds of single-answer pages into multi-answer, freshness-stamped citation surfaces in days. The second lever is turning the unique first-party data (248 live-tracked tools, a 890-article corpus, first-party analytics) into per-stat, dated, citable anchors and a captured star time-series nobody else can reproduce — the one content type every engine is forced to cite at origin. The third is opening the Chinese front door that is already a top referrer (native /zh editions, explicit Baiduspider/Sogou admission, Baidu push). Everything code-shippable is autonomous; the genuine ceiling-raiser — off-site corroboration (Reddit, Wikidata, WeChat/Baike) since ~91% of AI citations are third-party — is the human editor's job. Fastest wins: wire the FAQ helper site-wide, stamp freshness on the live-data pages, and harden IndexNow to ping on refresh.

## FAQ on every page (owner-requested) — design

DESIGN — one FAQ block at the bottom of EVERY page type, generated deterministically from data the page already holds (zero new authoring, so it stays truthful under the named-editor accountability), reusing the existing faqSection(rows,{heading}) helper (render.js:1525) which already returns {html, ld} = a visible <details> accordion PLUS FAQPage JSON-LD with byte-identical answer text.

WHICH QUESTIONS, PER PAGE TYPE (each answer 40-80 words, self-contained, subject named, sourced from real fields):
- Tool page (/stack/:slug): already live via toolFaq() — keep as the reference pattern ('What is X?','Is X free?','Is X open source?','Does X have an API/MCP server?','Can an AI agent self-signup for X?','What are the best alternatives to X?').
- Compare (/compare/:a-vs-:b): 'Is A or B better for {top use-case}?','What's the difference between A and B?','Which has more GitHub stars?','Is A or B cheaper?','Can I use A and B together?','Which should a solo founder pick?' — answers derived from stars/language/license/pricing/mcp fields.
- Best (/best/:cat): 'What is the best {category} for AI agents?','What is the best free/open-source {category}?','Which {category} has the most GitHub stars?','Which is best for production vs beginners?' — answered from the ranking logic.
- Alternatives (/alternatives/:slug): 'What is the closest alternative to X?','What are the best free alternatives to X?','Why replace X?' — from the alts cluster.
- Topic hub (/topics/*): the 4-6 questions that define the entity — 'What is {term}?','How does {term} work?','What are the best tools for {term}?' — paired with a DefinedTerm definition.
- Calculators: answers ARE the computed values — 'How much VRAM does an 8B model need in fp16?' → the preset's computed number; plus a HowTo of the input steps.
- Sections + homepage: 'Who writes dreaming.press?','Is it free?','How often is it updated?','Who is the editor?' — from org data.
- Articles (all ~890): backfilled from existing faq: frontmatter, else synthesized from takeaway bullets + question-form H2s (emit only when >=2 clean pairs, answers = real article prose).

HOW GENERATED: a small per-template generator (compareFaq/bestFaq/altsFaq/hubFaq/calcFaq) mirroring toolFaq(); optionally ranked by real demand from a questions.js ledger (referrer query strings + corpus co-mention + autocomplete) so phrasing matches what users actually type, falling back to the data template.

WHAT SCHEMA: FAQPage with mainEntity[] of Question→acceptedAnswer, but for pages whose true purpose is NOT Q&A (compare/best/calc/hub/home), emit the Questions inside a @graph whose primary node keeps the honest @type (TechArticle/CollectionPage/ItemList/WebApplication) referencing them — this is the clean-markup fix for Google's 'FAQ on non-FAQ pages' spam concern, and AI engines still extract the Q&A. Google retired the FAQ rich RESULT (May 2026) but the FAQPage TYPE is not deprecated and is still parsed by ChatGPT/Perplexity/Gemini/AI-Overviews/Baidu.

PLUMBING: pipe every Q&A pair into the page's .md twin (append a ## FAQ section) and into /api (per-record faq[] arrays + a new /api/faqs.json, CC-BY), and list the highest-value FAQ hubs in llms.txt — so the LLM crawlers get pre-chunked, attributable answer pairs directly. Byte-parity between schema and visible text is mandatory (never inject-only).
